01
Backend Go · PostgreSQL · Redis
Distributed Task Scheduler

How do you reliably schedule millions of background jobs across multiple workers — without duplicates, without loss, and with visibility into what's actually running?

+
What I Explored
  • At-least-once vs exactly-once delivery tradeoffs
  • Distributed locking using Redis SETNX with TTL
  • Worker heartbeat and dead-letter queue design
  • Backpressure handling under high enqueue load
  • Cron expression parsing and timezone edge cases
Architecture Decisions
  • Polling vs push-based worker wake-up
  • Job state machine: pending → running → done / failed
  • Idempotency keys for safe retries
  • Priority queues without starvation
Engineering Challenge

The hardest part wasn't scheduling — it was ensuring a crashed worker's jobs got reclaimed without being double-executed. Solving this with Redis TTL-based leases while keeping latency low required multiple iterations on the lock renewal strategy.

02
Platform Node.js · Kafka · Elastic
Real-Time Log Analytics Pipeline

Turning high-volume application logs into queryable operational signals — in near real-time, without drowning the primary database.

+
What I Explored
  • Stream processing vs batch ingestion tradeoffs
  • Kafka partition strategy for log ordering guarantees
  • Elasticsearch index lifecycle management
  • Schema evolution across log format changes
  • Anomaly detection with rolling window aggregates
Observations
  • Consumer lag is the single most important metric
  • Structured logs dramatically reduce query complexity
  • Retention policies need thought before ingestion
  • Alerting on absence is as important as presence
Engineering Challenge

Handling log spikes during deployments — where ingestion rate would briefly 10× — required careful consumer group scaling and thinking about what data could be safely sampled versus what needed full fidelity.

Automation Python · FastAPI · PostgreSQL
Intelligent Workflow Automation Engine

Building a rule-based + AI-assisted engine that can route, transform, and act on structured business events — without hard-coding every decision path.

+
What I Explored
  • Rule engine design vs ML classification tradeoffs
  • Workflow state persistence across async steps
  • Integrating LLM calls as conditional decision nodes
  • Audit logging for non-deterministic automation
  • Rollback semantics in multi-step pipelines
Design Reasoning
  • Rules + AI hybrid: interpretable by default, smart at edges
  • Every action stored with input context for debugging
  • Confidence thresholds gate AI-driven decisions
  • Human-in-the-loop hooks for low-confidence paths
Engineering Challenge

Non-deterministic AI steps made testing painful. I built a replay harness that could re-run any historical workflow against a new model version — making it possible to measure regression without waiting for production events.
